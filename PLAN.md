### 50.3 — Починить date-зависимые e2e-тесты переноса дня (падали по воскресеньям)

- **Статус:** [x] закрыта (2026-10-11; ветка `task/50-plan-md-optimization`).
- **Источник:** прогон e2e перед PR задачи 50 (запрошен владельцем) — 3 теста упали: `флоу: перенос дня и тренировка альтернативного набора`, `план недели: пропуск, отмена пропуска и перенос дня`, `противопоказания: «больше не показывать» для программы`; все — `Found 0 widgets with text "Перенести на сегодня"`.
- **Причина:** тесты строили «соседний день» через `day2Weekday` (wrap `воскресенье → суббота`), а программа активируется «сегодня». В воскресенье суббота — прошлый день недели, `_isProgramActiveOn` его отсекает, и кнопка переноса не отображается (в Mo–Сб «завтра» — будущий день той же недели, тесты проходили; 2026-09-26 — суббота, 20/20 ✅).
- **Рабочий план:**
  1. Добавить в `integration_test/app_flow_test.dart` хелперы: `nextDay()` (реальный «следующий день» = `now + 1 сутки`), `weekMonday()`, `goToWeekOf()` (переход на неделю, содержащую дату; на Mo–Сб — no-op, в воскресенье — на неделю вперёд).
  2. В трёх тестах: день 2 = `nextDay().weekday`; перед поиском `Перенести на сегодня` — `goToWeekOf(nextDay)`; в конце флоу-теста переноса вернуться на текущую неделю.
  3. Прогнать полный e2e (`flutter test integration_test -d linux`), все тесты зелёные.
- **Реализовано (2026-10-11):** хелперы добавлены — `nextDay`, `weekMonday`, `goToWeekOf` (навигация от **отображаемой** недели по заголовку), `weekRescheduleButtonForDay` (в следующей неделе у обоих дней программы есть перенос), общий `displayedWeekLabel`; три теста переведены на реальный «следующий день» с навигацией по неделям; `flutter analyze` — 0 замечаний; e2e-прогон — 20/20 ✅ (07:55).
- **Проверка:** e2e зелёный в любой день недели (в т.ч. воскресенье); Mo–Сб поведение тестов не изменилось (`goToWeekOf` — no-op).

### 51.5 — История: постоянный размер ячеек календаря на широком экране

- **Статус:** [x] выполнена (2026-10-11).
- **Источник:** п.5 `TASKS.md`: «История. Календарь. Широкий экран. При переключении месяцев размер ячеек меняется… Нужно сделать контейнер с одинаковой шириной, чтобы размер всегда был одинаков для разных месяцев».
- **Причина (2026-10-11):** в `MonthGridView` (`lib/app/widgets/calendar/month_grid.dart`, ветка `fillHeight`) размер ячейки считался как `min(availableWidth / 7, availableHeight / weekCount)`, то есть зависел от числа недель в месяце (4/5/6). На широком экране лимитирует высота → размер разный для разных месяцев.
- **Рабочий план:**
  1. Считать размер независимо от `weekCount`: `cell = min(availableWidth / 7, availableHeight / 6)` — резерв под максимум 6 строк; ширина контейнера `7*cell + 6*columnGap`. Месяцы с 4/5 недель оставляют свободное место снизу, размер ячейки постоянный, ячейки квадратные.
  2. Тест: два месяца с разным числом недель при широком экране → одинаковый размер `MonthDayCell`.
- **Реализовано (2026-10-11):** в `month_grid.dart` введён `const int maxWeekRows = 6`; бюджет высоты и ячейка считаются по нему (`availableHeight / maxWeekRows`), поэтому размер и ширина контейнера не зависят от числа недель месяца. Добавлен отдельный тест `test/app/widgets/calendar/month_grid_test.dart` (февраль 2027 — 4 недели, октябрь 2026 — 5, ноябрь 2026 — 6 → одинаковый размер ячейки и квадратность); тест падает без фикса и проходит с ним.
