### 57.1 — «Сохранить» в форме упражнения без выбранных мышц — тихий no-op
- **Статус:** ✅ 2026-10-31, PR #274 (46cb862, CI main ✓). Гейты: 1355/1355, формат/анализаторы 0, e2e 19/19. task-reviewer: SHIP; design-reviewer: APPROVE (Low-фикс `alignment: 0.5` в `ensureVisible` применён в ветке). Ретест эмулятора (TC-205): PASS.
- **Проблема (QA, TEST_PLAN TC-007, 2026-10-25):** в форме упражнения при заполненном имени валидация имени работает («Введите название»), но тап «Сохранить» БЕЗ выбранных групп мышц — тихий no-op: нет валидационного сообщения/снекбара, форма молча остаётся открытой, пользователь не понимает, что мешает сохранить. Подтверждено ретестом в прогоне релиза (историческая заметка «не срабатывает» подтверждена как дефект UX).

- **Решение/Тест:** при пустом списке мышц тап «Сохранить» должен давать явное валидационное сообщение/снекбар (или пометку у блока мышц); ретест — `TEST_PLAN.md` TC-007 (проверка валидационного сообщения при пустых мышцах).

### 57.2 — Поведение resumed-тренировки после импорта БД (нужно решение владельца)
> **Решение владельца (2026-10-25):** импорт БД обязан чистить локальные чекпойнты (в момент импорта не может быть начатой тренировки); чекпойнт вводится TTL — не восстанавливать тренировки старше 12 часов от `startedAt`.

- **Статус:** ✅ 2026-10-25, PR #269 (d809b97). task-reviewer: SHIP (после добавления регресс-теста сброса `restoredCheckpoint` дефолтным клирером в `sync_controller_test`). 1349/1349. **Реализовано:** Фикс A — `SyncController.importDatabase()` после успешного импорта вызывает `_checkpointClearer()` (новый typedef `CheckpointClearer`, дефолт: `WorkoutCheckpoint.clear()` + `restoredCheckpoint = null`) до `_setStatus(importDone)`, т.е. до `restartApp()`; Фикс B — `bootstrap()` через `_restoreCheckpoint(sl)`: TTL (`WorkoutCheckpoint.ttl = Duration(hours: 12)`, `startedAt` строго старше — удаление) и факт (`ProgramRepository.getDay(programDayId)` != null); невалидный снимок удаляется, redirect не происходит. Тесты: bootstrap ×3 (свежий валидный / граница TTL ровно ttt → удалён / день 999999 → удалён), sync_controller ×1 дефолтный клирер через fake path_provider (зеркало lib-стороны фикса A), settings_screen ×1 ассерт clear. Гейты зелёные.
- **Проблема (QA, TEST_PLAN TC-175, 2026-10-25):** после импорта БД (диалог «Импорт выполнен» → «OK» → перезапуск приложения) приложение открылось на экране активной (resumed) тренировки — восстановление checkpoint из опрокинутого состояния. Неясно, ожидаемое ли это поведение (checkpoint переживает импорт/перезапуск) или неожиданное: при импорте чужой/целиком замещающей БД восстановленная тренировка может ссылаться на несуществующие в новых данных сущности.
- **Причина (диагностика по коду, 2026-10-25):** три звена: (1) `workout_checkpoint.json` пишется на диск по таймеру 5с/подходам/фону и удаляется только при `dispose()` с фазой `finished`/`idle` (`workout_run_screen.dart:160-177`) — force-stop незавершённой тренировки оставляет файл; (2) `restoredCheckpoint` — глобал, читается один раз в `bootstrap()` (`bootstrap.dart:93`); (3) `restartApp()` (импорт: `settings_screen.dart:428`) пересоздаёт роутер через `AppRouter.create()`, который переиспользует **stale in-memory `restoredCheckpoint`** и redirect'ит на `/workout/run` (`router.dart:63-70`) — локальный чекпойнт не согласован с заменённой БД (ID дня может не существовать).
- **Рабочий план (утверждён, реализация — 57.2):**
  1. **Фикс A (безусловная чистка при импорте):** в `SyncController.importDatabase()` после успешного `_syncService.import()` — `await WorkoutCheckpoint.clear()` и `restoredCheckpoint = null` **до** `restartApp()`; пере-созданный роутер не получает stale-value.
  2. **Фикс B («по факту» + TTL):** в `bootstrap()` после `WorkoutCheckpoint.load()` — валидация: (а) TTL — `startedAt` старше `Duration(hours: 12)` (константа в `WorkoutCheckpoint`, `static const ttl`) → файл удалён, `restoredCheckpoint = null`; (б) факт — `programDayId` существует в текущей БД (репозиторий из `sl` готов на месте boot; испорченный `fromJson` уже гасится try) → иначе удалить/не восстанавливать.
  3. **Тесты:** `bootstrap_test` — старше 12ч → null+файл удалён; `programDayId` отсутствует → null; свежий валидный → восстанавливается; `sync_controller_test` — успешный импорт чистит чекпойнт и сбрасывает `restoredCheckpoint` до restartApp. Регресс: существующие тесты живы.
     - Исполненное: логика дефолтного клирера проверяется в `sync_controller_test` (тест живёт там, а не в `settings_screen_test` — зеркало lib-стороны фикса A: контроллер импортирует глобал из `app/bootstrap.dart`); виджет-тест экрана (`settings_screen_test`) дополнительно инъецирует clearer-счётчик на вызов. Итог: +4 теста (3 bootstrap + 1 sync_controller + ассерт в settings экране). 1349/1349.
  4. **TC:** обновить `TEST_PLAN.md` TC-175-хвост (старт → force-stop → импорт → перезапуск → `/home`, без resumed) — append-режим android-tester по завершении.

### 57.3 — Восстановленная тренировка не переписывает чекпойнт заново: повторный force-stop теряет её навсегда
- **Статус:** ✅ 2026-10-28, PR #270 (c1954a3). task-reviewer: SHIP. 1350/1350, e2e 19/19.
- **Проблема (QA, TEST_PLAN TC-202, 2026-10-25):** ретест 57.2 (PR #269 стабильно PASS по всем кейсам: TC-199–TC-201) обнаружил соседний дефект: тренировка, восстановленная из чекпойнта (экран открылся по redirect'у), потребляет файл чекпойнта на диске (`_initLoad`: load → clear) и далее НЕ переписывает его: таймер 5с (`_saveCheckpoint()`) не срабатывает, повторный force-stop/краш на восстановленной тренировке теряет её навсегда (перезапуск открывает /home, файла нет, предупреждений нет).
