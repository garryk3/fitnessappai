не удаляются и не переписываются.

## Статусы

- `PASS` — результат соответствует ожидаемому.
- `FAIL` — найдена проблема (приложение ведёт себя неверно/падает/теряет данные).
- `SKIP` — сценарий не выполнялся.
- `BLOCKED` — выполнение невозможно из-за окружения.

## Формат записи сценария

1. Перед выполнением зафиксируйте: `TC-<NNN>`, название, экран/область, предусловия, шаги, ожидаемый результат.
2. После выполнения — фактический результат, статус, дата, при необходимости доказательства (дамп UI, logcat, скриншот) и заметки.

## TC-001 — Старт приложения без системных диалогов

- **Экран/область:** стр (запуск, `bootstrap`)
- **Предусловия:** разрешения сброшены: `adb shell pm revoke com.example.fitnessappai android.permission.POST_NOTIFICATIONS`; установлена свежая debug-сборка.
- **Шаги:**
  1. Запустить приложение: `adb shell am start -n com.example.fitnessappai/.MainActivity`.
  2. Подождать ~8 с, снять `uiautomator dump`.
- **Ожидаемый результат:** приложение открывает Главный экран; системный диалог «Allow notifications» НЕ появляется; системный экран «Alarms & reminders» НЕ открывается.
- **Фактический результат:** на дампе — главный экран («Главная», «К программам», вкладки), системных диалогов и экрана будильников нет.
- **Статус:** PASS
- **Дата:** 2026-09-21
- **Заметки:** ранее (дефект 40.4) при старте вызывался `requestExactAlarmsPermission()` — после «Allow» сразу открывался «Alarms & reminders». Фикшен убран из `ReminderService.initialize()`.

## TC-002 — «Разрешить уведомления» запрашивает только уведомления

- **Экран/область:** Настройки → Уведомления
- **Предусловия:** `POST_NOTIFICATIONS` отозван через `pm revoke`; приложение запущено, открыт экран Настройки.
- **Шаги:**
  1. Зафиксировать в дампе кнопку «Разрешить уведомления» (дамп показывает «Уведомления отключены»).
  2. Тапнуть по центру кнопки.
  3. Снять дамп — убедиться, что открылся только системный диалог «Allow <app> to send you notifications?».
  4. Тапнуть «Allow».
  5. Снять дамп.
- **Ожидаемый результат:** шаг 3 — только диалог уведомлений, НЕ экран «Alarms & reminders»; шаг 5 — мы остались в настройках, «Уведомления включены», кнопка «Разрешить уведомления» исчезла; системный экран будильников не открывался.
- **Фактический результат:** шаг 3 — открыт только диалог уведомлений; шаг 5 — настройки, статус «Уведомления включены», осталась только кнопка «Настроить точные будильники». `dumpsys package`: `POST_NOTIFICATIONS: granted=true`.
- **Статус:** PASS
- **Дата:** 2026-09-21
- **Заметки:** дефект 40.4: раньше обе кнопки вызывали один `requestPermissions()` и дёргали оба разрешения разом. Теперь кнопка вызывает `requestNotificationsPermission()` (только уведомления).

## TC-003 — «Настроить точные будильники» открывает только системный экран будильников

- **Экран/область:** Настройки → Уведомления
- **Предусловия:** уведомления включены (TC-002), точные будильники отключены.
- **Шаги:**
  1. Тапнуть кнопку «Настроить точные будильники».
  2. Снять дамп — убедиться, что открылся системный экран «Alarms & reminders» и уведомления при этом не запрашиваются.
  3. Включить тумблер «Allow setting alarms and reminders» (элемент `checkable="true"` на экране настроек Android), нажать BACK.
  4. Снять дамп.
- **Ожидаемый результат:** шаг 2 — только системный экран «Alarms & reminders»; шаг 4 — вернулись в настройки со статусом «Точные будильники включены», кнопка исчезла.
- **Фактический результат:** шаг 2 — открыт «Alarms & reminders»; шаг 4 — «Уведомления включены», «Точные будильники включены». `adb shell appops get` → `SCHEDULE_EXACT_ALARM: allow`.
- **Статус:** PASS
- **Дата:** 2026-09-21
- **Заметки:** SCHEDULE_EXACT_ALARM — специальный app-op: выдача возможна только через системный экран (Android 12+). Кнопка вызывает `requestExactAlarmsPermission()` (только будильники).
