# Аудит дизайна и юзабилити FitnessAppAI

**Дата:** 17.09.2026
**Метод:** дизайн-аудит текущего UI в OpenDesign (скилл `design-review`) по
HTML-борду, воссозданному из реального кода приложения (Material 3, seed
`#7E57C2`, светлая/тёмная темы, компактный/расширенный макеты, настоящие
RU-строки из `app_ru.arb`) + сверка всех выводов с исходным кодом Flutter.
**Маркировка:** ✅ подтверждено кодом · ⚠️ артефакт борда (в коде не так).

Исходный отчёт OpenDesign: `design-audit-report.md` в проекте
`fitnessappai-design-audit` (полный отчёт OD, 417 строк). Ниже — итоговая
сводная версия с приоритетами P0/P1/P2.

---

## Резюме

Базис уже современный: реальные токены `ColorScheme.fromSeed`, обе темы,
адаптивные NavigationBar/NavigationRail, чистый ритм 8/12/16, хороший
info-scent в фазе тренировки. Блокирующих дефектов в самом коде немного —
главные: **уменьшенные touch-target'ы**, **теневая «не-M3» элевация** и
**статусы в `error`-красном**. Часть «проблем» из аудита OD оказалась
артефактами моего HTML-борда (эмодзи-иконки, вторая серия графика,
двухпанельный макет, усечённые лейблы рейла) — в реальном коде их нет.

**Сильные стороны (подтверждены).** Контраст всего используемого текста
≥5.56:1 в обеих темах (нет нарушений 4.5:1); грамотный номерной экран
тренировки (история подходов + заголовок «упражнение N из M»); глубокое
погружение в тренировку (NavigationBar скрыт в фазе упражнения/отдыха).

## P0 — критично (исправить обязательно)

### P0-1 · Уменьшенные touch-target'ы (M3≥48dp / iOS≥44pt) ✅
Код местами сознательно уменьшает цели касания:
- `workout_run_screen.dart:510` — `visualDensity: VisualDensity.compact`
  (иконка «стоп» на фазе отдыха);
- `workout_run_screen.dart:1225-1226` и `week_plan_screen.dart:787,814` —
  чипы мышц и дни недели с `VisualDensity.compact` +
  `MaterialTapTargetSize.shrinkWrap`;
- `muscle_panel.dart:93-94` — панель мышц `compact`/`shrinkWrap`;
- `day_detail_screen.dart:182` — `VisualDensity.compact`.

**Рекомендация.** Для не-первичных элементов оставить `shrinkWrap` только
там, где это осознанный компромисс (плотные чипы-теги), но всем
icon-only-контролам и дням недели вернуть цель ≥44–48px (убрать/disabling
`compact`), плюс `Tooltip`/`Semantics.label` (см. P1-2).

### P0-2 · Тёмная элевация вместо теней (M3) ✅
- `app_theme.dart:31-37` — NavigationBar: `elevation: 3` + `shadowColor:
  black.withValues(alpha:.3)` + визуальный бордер-тень снизу;
- `app_theme.dart:44-50` — Card: `elevation: 2` + тень;
- `app_theme.dart:66-67` — SearchBar: `elevation` тень.

M3 строит глубину тональной элевацией (surface-container), тени — только
для плавающих поверхностей (FAB, bottom sheet, dialog). Результат — слегка
«материал 2018».

**Рекомендация.** Убрать тени у Card/SearchBar/NavigationBar (заменить
`elevation` на 0, оставить контейнерные поверхностные цвета), оставить
точечную тень у FAB и dialogs; `surfaceTintColor` — чтобы Android получал
tonal tint, а iOS не дублировал тень.

## P1 — следует исправить

### P1-1 · Статусы «Пропущено» в error-красном ✅
`status_badge.dart:34-43` — `scheduleSkipped`/`pastSkipped` рендерятся
`colorScheme.error`/`onError`. По M3 и iOS HIG красный зарезервирован за
ошибками/деструктивными действиями; пропущенная тренировка — нейтральное
событие прошлого.

**Рекомендация.** Задать единый цветовой контракт статусов: performed
= primary, planned = surfaceContainerHighest, rescheduled = tertiary,
skipped = neutral/outline + иконка; красный — только для реальных ошибок
(удаление, сбой синхронизации).

### P1-2 · Статусный словарь: «Выполнено» на карточке активной программы ✅
`home_screen.dart:251-252` — бейдж с `StatusBadge(status: todayStatus!)`
на блоке «Активная программа», в то время как в списке программ тот же
объект подписан `programActive` («Активная»). Один объект — два разных слова
и веса.

**Рекомендация.** Одно из двух: (а) карточка главной показывает статус
сегодняшней тренировки отдельной строкой, бейдж программы — только
«Активная»; (б) убрать бейдж с главной и дать play-аффорданс.

### P1-3 · Emoji не используются — НО иконки без label ✅
Приложение использует настоящие `Icons.*` (Material Symbols) — 
⚠️ артефакт борда: эмодзи в отчёте OD были только в моём HTML-рендере.
**Но** многие icon-only-контролы не имеют `Tooltip`/семантики:
`exercises_screen.dart:397` (play), `home_screen.dart:71` (settings gear),
`profile_screen.dart:427` (delete замера), `progress_screen.dart`
(chevron-переключение недели).

**Рекомендация.** Каждому icon-only-контролу — `Tooltip` (для mouse/keyboard
и discoverability) + `Semantics.label`; удаление замера — через
confirm-диалог (сейчас прямое деструктивное действие с иконкой корзины).

### P1-4 · Шесть вкладок навигации (M3/iOS: ≤5) ✅
`adaptive_navigation.dart:33-112` — 6 `NavigationDestination`; M3 и iOS HIG
рекомендуют ≤5. Плюс в коде `adaptive_navigation.dart:144` для компактного
бара явно задан `labelBehavior: alwaysHide` (при этом тема в `app_theme.dart:36`
— `alwaysShow`): на телефоне лейблы вкладок скрыты, что при 6 разделах
ухудшает узнаваемость. ⚠️ На борде я показал лейблы — в реальном приложении
их нет.

**Рекомендация.** Сжать до 5 разделов (например, «История/Прогресс» в один)
и/или вернуть `alwaysShow` лейблы; минимум — сверить `alwaysHide` с
намерением (M3 для 3+ вкладок рекомендует показывать лейблы).

### P1-5 · Графики: контраст сетки и оси ✅ (но не то, что писал OD)
Реальный BarChart «Тренировки по срезам» (`progress_screen.dart:255-363`):
- стержни — одна серия `primary` (✅ контраст OK; ⚠️ вторая сессия из отчёта
  OD не существует);
- сетка `outlineVariant.withValues(alpha: 0.3)` + бордер `outlineVariant`
  (`progress_screen.dart:299-317`) — при alpha 0.3 контраст сетки ниже
  3:1 (это подтверждённый недочёт, но OD её оценил «в лоб», без alpha);
- tooltip уже есть (`barTouchData`, `progress_screen.dart:258-271`) —
  ⚠️ OD писал «нет tooltip», это артефакт борда;
- подписи периодов снизу есть, но **нет значений по левой оси** и единиц
  (`titlesData`, `progress_screen.dart:319-348`).

**Рекомендация.** Сетку поднять до `outline` (или убрать вовсе, оставив
ось + подсветку активного значения); добавить значения по оси Y с единицами
и annotate последней точки; обернуть график в `Semantics` с описанием тренда.

### P1-6 · Настройки: три виджета для булевых значений ✅
`settings_screen.dart` — тема через `SegmentedButton<ThemeMode>` (строки
105-...), звук/уведомления через `SwitchListTile` (строка 158 и далее).

**Рекомендация.** Унифицировать булевы переключатели в один виджет
(switch-list), отполировать off-состояние тумблера; для тема-мода оставить
SegmentedButton, но проверить off-состояние.

### P1-7 · Двухпанельный макет в коде не используется ⚠️
Отчёт OD хвалил TwoPaneListDetail и ругал отсутствие синхронизации
выделения. **Реальность:** класс `TwoPaneLayout` есть
(`two_pane_layout.dart:4-26`), но **нигде не используется** — в коде найден
только его дефинишн. Таблет получает `NavigationRail` + обычные экраны
(`adaptive_navigation.dart:122-135`), а не список+детали.

**Рекомендация (возможность).** Либо выпилить мёртвый `TwoPaneLayout`,
либо подключить его на Программы/План/Прогресс для истинного
list+detail на ≥840dp (с синхронизацией выделения в списке).

## P2 — полировка

1. **Экран итогов тренировки — тройной primary** ✅
   `workout_run_screen.dart:1159-1161` (галка), `1240-1243`
   («Тренировка сохранена»), `поднимись` кнопки `primary` — три primary в
   одном окне. Оставить primary галку, надпись «сохранено» — в
   `onSurfaceVariant`.
2. **Чипы «Задействованные мышцы» конфликтуют со статусом** ✅
   `workout_run_screen.dart:1221-1224` — `Chip` с фоном
   `primaryContainer` (звучит как «Выполнено»). Использовать
   secondaryContainer/assist-chip.
3. **AppBar title bold 600** ✅ `app_theme.dart:25-29` — M3 `titleLarge`
   обычно 500. Тривиально.
4. **«Повторения — левая»** ✅ `workout_run_screen.dart:940-943` — утечка
   модели «левая/правая» в интерфейс: показывать сторону только при
   реально двойном подходе (side-подходе) или формулировать как
   «Левая сторона».
5. **Динамический размер шрифта** — 11px (`labelSmall` в бейджах, рейле,
   лейблах статистики) ломается при textScale 1.3–2.0; тесты на textScale
   не покрыты. Проверить на 1.3 и 2.0.
6. **Безопасные зоны** — проверить insets на iOS (навбар + FAB над
   home-indicator; форма ввода веса/повторов не прячется под клавиатуру).

## Рекомендуемый порядок работ (по effort/impact)

1. Touch-target'ы + label'ы иконок (P0-1) — быстро, высокий эффект.
2. Тональная элевация вместо теней (P0-2) — одна тема, глобальный эффект.
3. Статусный словарь + убрать красный «Пропущено» (P1-1, P1-2).
4. Оси/сетка графиков (P1-5) + семантика.
5. Унификация настроек (P1-6), Tooltip'ы (P1-3).
6. Дальше — P2 (экран итогов, чипы мышц, dynamic type, безопасные зоны).

## Ограничения аудита

Статический анализ по рендеру борда + коду. Анимации, ripple/motion,
RefreshIndicator, сплэш-видео, звуки и все `TextFormField`-формы не
«прогонялись» визуально (упомянуты по документации борда).
